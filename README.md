# CI-DI-project

Команда `check --only tests` запускает pytest в каталоге выбранного проекта.
Подготовьте его окружение и установите в него pytest и зависимости приложения.
Из каталога утилиты выполните, например:

```sh
python3 main.py check --only tests --project ../web-app --python ../web-app/.venv/bin/python
```

Без `--python` используется Python самой утилиты. Таймаут по умолчанию —
300 секунд. Его можно изменить через `--test-timeout`. Вывод pytest виден в
терминале. В журнале сохраняются начало и итог проверки. По умолчанию журнал
создаётся в `logs/` в текущем каталоге. Другой путь задаётся через `--log-file`.

| Код завершения | Значение |
|---|---|
| 0 | Тесты прошли или пользователь запросил справку. |
| 1 | Не удалось открыть журнал или выполнить проверку. Сюда относятся падение теста, пустой набор тестов и таймаут. |
| 2 | Ошибка аргументов, например нулевой таймаут. |
| 130 | Пользователь прервал выполнение проверки через Ctrl+C (Python получил KeyboardInterrupt). |

Для тестирования самой утилиты выполните из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest
```

После активации окружения весь набор также запускается командой `pytest` из
корня репозитория. Чтобы выполнить только юнит-тесты трёх модулей, укажите
их файлы:

```sh
.venv/bin/pytest tests/test_pytest_runner.py tests/test_log.py tests/test_main.py
```

Юнит-тесты проверяют выбор интерпретатора, обработку ошибок pytest, запись
журнала и коды завершения CLI. Интеграционные тесты в `tests/test_cli.py`
запускают настоящий pytest во временном проекте, включая сценарий с таймаутом.
